# 노른 · NORN

**노른노른하게, 영상을 굽다.**

내 컴퓨터의 사진·영상을 선택하고, 브라우저에서 장면을 편집해 영상과 SNS 게시 자료를 만드는 영상 스튜디오입니다. 로그인 사용자의 기본 흐름은 **사이트 접속 → 프로젝트 워크스페이스 → 프로젝트 생성/열기 → 파일·폴더 선택 → 편집 → 영상 생성 → 다운로드**입니다. 로그인 없이 사용할 때는 브라우저의 단일 로컬 작업으로 시작합니다. 일반 사용자가 Python, FFmpeg, Ollama를 설치하거나 로컬 서버를 실행할 필요가 없습니다.

브라우저·프로젝트 작업 흐름 기준: **2026-10-20**. 이 문서는 사용 방법과 소스의 구성에 관한 안내이며, 배포·실기기 검증 완료를 뜻하지 않습니다. 검증 기록은 [기능/검증 상태](docs/STATUS.md)에서 별도로 확인합니다.

## 사이트에서 시작

서비스 주소: [노른](https://norn.designboard.net/) · [연결 점검](https://norn.designboard.net/setup.html)

| 단계 | 하는 일 |
|---|---|
| 1. 프로젝트 선택 | 로그인하면 Firebase 프로젝트 워크스페이스가 열립니다. 기존 프로젝트를 열거나 `+ 새 프로젝트`로 영상 작업을 만듭니다. 프로젝트 생성 즉시 편집정보 저장 공간이 만들어집니다. |
| 2. 자료 선택 | 파일 선택으로 사진·영상·음악 여러 개를 고르거나 폴더 선택으로 자료를 불러옵니다. 원본은 Firebase에 업로드하지 않습니다. |
| 3. 자동 제작·장면 편집 | 자동 제작으로 첫 구성·타이틀·문구·전환·선택 음악을 배치하고, 사용할 자료·순서·구간·비율을 직접 수정합니다. |
| 4. 영상 생성 | 브라우저가 자료를 읽고 지원하는 형식으로 결과 영상을 만듭니다. 진행 상태와 실제 출력 형식을 확인합니다. |
| 5. 워크스페이스 복귀 | 편집정보를 Firebase에 저장하고 프로젝트 목록으로 돌아갑니다. 프로젝트 카드를 다시 열어 이어서 편집할 수 있습니다. |
| 6. 결과 저장 | 생성 영상, 편집 JSON, SNS 문구를 다운로드합니다. 게시 준비 ZIP에는 생성 영상과 편집정보·문구가 들어가며 원본은 들어가지 않습니다. |

자료 선택은 내 컴퓨터에 있는 파일을 읽을 수 있도록 허용하는 동작입니다. 원본을 웹 서버에 업로드하는 단계가 아닙니다. 서버 주소·연결 토큰·터미널 명령은 기본 작업 동선에 필요하지 않습니다.

## 장면 편집과 삭제

작업실의 기본 동선은 **자료 추가 → 장면 편집 → 영상 저장**입니다. 사진·영상의 제목, 문구와 사진 재생 시간은 바로 편집할 수 있고, 글씨 꾸미기·전환·음악은 필요할 때 펼칩니다. 편집 JSON 열기·백업은 자료 보관함의 **작업 불러오기·관리**, 출력 설정과 여러 버전 저장은 **버전 관리**에 있습니다.

타임라인 카드의 **×**로 해당 장면을 바로 삭제하거나, 카드를 선택한 뒤 **선택 장면 삭제**를 누릅니다. 타임라인에 초점이 있으면 `Delete`·`Backspace`도 사용할 수 있습니다. **되돌리기**는 삭제한 장면의 내용·순서·선택까지 복구하고 **다시 실행**으로 삭제를 반복할 수 있습니다. `Ctrl/⌘ Z`, `Ctrl/⌘ Shift Z`도 지원합니다. 제목·문구 등 입력 중에는 입력창의 단축키 동작을 유지하며, 영상 생성 중에는 타임라인 변경을 막습니다.

장면을 모두 삭제해도 원본 자료는 보관함에 남습니다. 모바일에서는 자료, 미리보기, 타임라인, 장면 속성 순서로 배치하고 각 삭제 버튼을 항상 표시합니다.

## 원본과 편집정보

| 데이터 | 처리·저장 방식 |
|---|---|
| 원본 사진·영상·음악 | 사용자가 선택한 `File`과 임시 객체 URL로 참조합니다. 원본 파일의 복사본을 결과 폴더에 만들거나 원본을 이동·삭제·변경하지 않습니다. |
| 미리보기·렌더링 데이터 | 브라우저가 재생·합성에 필요한 데이터를 읽습니다. 임시 URL이나 메모리에 읽은 데이터가 원본의 영구 백업을 대신하지 않습니다. |
| 편집 JSON | 제목, 장면, 구간, 출력 설정, SNS 문구, 파일 식별용 메타데이터·해시를 저장합니다. 원본 파일의 바이트는 포함하지 않습니다. |
| 프로젝트 워크스페이스 | 로그인 사용자는 Firebase `users/{uid}/projects/{projectId}` 아래에 프로젝트 현재본·출력 버전과 프로젝트 저장 이력을 관리합니다. 원본·표본·절대 경로·임시 URL·로컬 연결 토큰은 전송하지 않습니다. |
| 생성 영상 | 렌더링을 완료한 결과물을 다운로드하거나, 지원 환경에서 사용자가 지정한 출력 위치에 저장합니다. |

페이지를 새로 열거나 다른 기기에서 JSON·계정 프로젝트를 복원한 뒤에는 **원본 파일 또는 폴더를 다시 선택**합니다. 프로젝트에 파일명만 남았다고 원본 접근 권한까지 복원된 것으로 표시하지 않습니다. 파일 종류·크기·해시가 맞는 유일한 후보로 다시 연결하며, 누락되었거나 중복 후보가 있는 자료는 사용자가 확인합니다.

원본 폴더를 선택해 읽었다고 그 부모 폴더까지 쓸 수 있는 것은 아닙니다. 기본 결과 저장은 다운로드입니다. 폴더 직접 저장은 해당 기능을 제공하는 브라우저에서 사용자가 출력 위치와 쓰기를 허용할 때 사용합니다. 웹사이트가 원본 옆에 `원본폴더업로드준비`를 자동 생성한다고 안내하지 않습니다.

## 브라우저 영상 생성 범위

출력 형식은 브라우저의 녹화 지원을 확인해 정합니다. H.264·AAC 코덱의 MP4 녹화를 지원하면 `.mp4`, 해당 조합을 지원하지 않지만 WebM을 생성할 수 있으면 `.webm`을 사용합니다. 단순한 MP4 컨테이너 지원만으로 다른 코덱을 MP4로 내보내지 않습니다. 결과 화면·다운로드·ZIP의 파일명은 실제 결과 MIME과 맞춥니다.

| 항목 | 브라우저 렌더러의 범위 |
|---|---|
| 출력 크기 | 480p·720p(기본)·1080p 선택. 장변 최대 1,920px, 전체 최대 1,920×1,080픽셀 분량. 세로 출력 포함 |
| 출력 길이·장면 | 최대 10분, 120장면 |
| 프레임레이트 | 기본 30fps. 렌더러가 받는 설정은 10~60fps이며 실제 프레임 처리 성능은 기기에 따라 달라짐 |
| 영상 배속 | 0.25~4배속. 실제 브라우저가 허용하지 않는 배속은 오류 안내 |
| 사진 움직임 | 정지 또는 줌 |
| 글씨 | 제공되는 10개 글씨 스타일 |
| 전환 | 바로 연결, 부드러운 겹침, 검정·흰색 전환, 상·하·좌·우 와이프 |
| 소리 | 장면 원음, 전체 음소거, 선택한 로컬 음악의 볼륨·시작점·반복·페이드 |
| 생성 방식 | 브라우저 실시간 합성·녹화. 영상 길이 정도에 준비 시간이 더해짐 |

생성 중에는 작업 탭을 열어 두세요. 처리 속도 때문에 중단되면 480p로 낮추거나 짧은 구간으로 나누어 생성하세요. 작업 상태의 상세 진단에서 중단 원인을 확인할 수 있습니다. 탭 숨김 등으로 안정적인 처리가 불가능해지면 중단 안내 후 다시 시작합니다. 기존 FFmpeg용 고배속·일부 전환은 브라우저 출력 범위에 포함되지 않으며, 지원하지 않는 설정을 조용히 다른 효과로 바꾸지 않습니다.

사진·영상 파일을 선택할 수 있는 것과 그 파일의 코덱을 브라우저가 해석할 수 있는 것은 별개입니다. 읽지 못하는 파일은 원인을 표시합니다. 처리 한도는 긴 고해상도 자료의 성능 보장이 아닙니다. 세부 구현 원칙은 [브라우저 작업 흐름](docs/BROWSER_WORKFLOW.md)을 확인하세요.

## 자동 구성과 SNS 게시 준비

기본 자동 장면 배치는 선택한 자료와 길이 설정을 사용하는 **규칙 기반 구성**입니다. 연결한 AI 모델이 없는 상태에서 이미지의 내용·사건·음성을 AI가 분석했다고 표시하지 않습니다. 제목·장면 문구·게시문은 사용자가 확인하고 수정합니다. 로컬 Ollama를 이용하는 별도 AI 워크플로는 이 문서 말미에 있습니다.

숏폼·롱폼·타임랩스·사진 스토리·자유 편집 모드와 영상 비율을 선택하고, 버전을 복제해 순서·글씨를 각각 수정할 수 있습니다. 모드 선택만으로 정확한 하이라이트 추출이나 특정 출력 길이가 보장되는 것은 아닙니다. 예를 들어 1시간 영상을 30초로 줄이는 120배속 타임랩스는 브라우저의 4배속 상한을 넘으므로 고급 엔진 대상입니다.

게시 준비에서는 X·Instagram·TikTok·Threads·Facebook·네이버 블로그·네이버 클립·YouTube용 문구를 편집하고 직접 가져다 붙일 수 있도록 저장합니다. 내부 구성 지시문을 공개 게시문에 자동 복사하지 않습니다. SNS API 자동 발행은 제공하지 않습니다.

| 저장 항목 | 내용 |
|---|---|
| 영상 다운로드 | 현재 생성 결과의 실제 MP4 또는 WebM |
| 편집 JSON | 다음 작업에 사용할 프로젝트 설정과 파일 식별정보 |
| SNS 문구 | 채널별로 수정할 수 있는 게시 텍스트 |
| 게시 준비 ZIP | 생성 영상, 편집 JSON, SNS 문구·안내. 원본 사진·영상·음악은 제외 |

ZIP을 다른 기기로 옮기면 생성한 결과 영상은 사용할 수 있습니다. 다시 편집하려면 원본 자료도 해당 기기에서 별도로 선택해야 합니다. 게시할 채널이 해당 결과 형식을 받는지 확인하고, 필요한 경우 MP4 출력이 가능한 환경을 사용하세요.

## 운영자·개발자 안내

정적 UI의 원본은 `public/`이고, `npm run build`가 배포용 `dist/`를 만듭니다. 루트 HTML을 유지하는 배포에서는 `npm run sync:root`로 진입 파일을 동기화합니다. 정적 호스팅은 사이트를 제공하고, 기본 편집·영상 생성은 사용자의 브라우저에서 실행합니다.

Google 로그인 사용자는 프로젝트 워크스페이스에서 계정별 프로젝트 생성·저장·목록·재열기·삭제와 저장 충돌 방지를 사용합니다. 프로젝트 안의 `history/{revision}`은 편집 저장 이력이며, 프로젝트 카드의 작업 단위와 구분합니다. `public/firebase-config.json`에 지정된 계정 설정을 사용하며 로그인 성공은 실제 인증 응답으로 판단합니다. 로그인 연결이 없어도 기본 파일 선택·편집·다운로드 흐름을 사용할 수 있도록 구성합니다.

Firebase 운영 연결 도우미는 운영자가 Node.js 22 이상을 설치한 환경에서 실행합니다. 일반 사용자에게 요구하는 설치 단계가 아닙니다.

```bash
bash scripts/connect-firebase.command
```

도우미는 본인 Google 승인과 조회된 **노른 전용 프로젝트** 선택을 요구합니다. 실제 프로젝트·Google 로그인 제공자·허용 도메인·Firestore 규칙·호스팅 연결을 각각 확인합니다. 소스 빌드 성공과 운영 도메인·로그인 성공은 별도 검증 항목입니다.

### 검증 명령

다음 명령은 개발·회귀 검사에 사용하며 일반 사용자의 서비스 시작 단계가 아닙니다.

```bash
npm test
python3 -m unittest discover -s tests -p 'test_*.py' -v
npm install --ignore-scripts
npm run test:rules
python3 -m pip install playwright
python3 -m playwright install chromium
python3 tests/ui-live.py ui-results
npm run build
```

Firestore 검사는 `demo-norn` 에뮬레이터를 사용하며 운영 계정 OAuth 검증을 대신하지 않습니다. 운영 `/setup.html`의 **저장·복원·이력 검사**는 사용자가 직접 Google 로그인을 완료한 뒤 작은 임시 프로젝트를 생성해 history 저장·복원을 확인하고 즉시 삭제합니다. 기존 `tests/ui-live.py`와 Python 검사는 로컬 엔진의 회귀 검사입니다. 브라우저 단독 작업 흐름의 검증은 **로컬 엔진을 실행하지 않은 상태**에서 자료 선택부터 생성 결과 재생까지 별도로 확인해야 합니다. 작은 합성 자료의 검사를 실제 사용자 원본·모든 기기·긴 4K 영상의 검증으로 확대 해석하지 않습니다.

## 고급 선택 기능: 기존 Python·FFmpeg·Ollama 엔진

기존 로컬 엔진은 네이티브 FFmpeg 기능과 로컬 Ollama 분석이 필요한 사용자를 위한 별도 선택 기능으로 유지합니다. 위의 브라우저 기본 흐름을 시작하기 위한 필수 프로그램이 아닙니다. [기존 엔진 운영 점검표](docs/OPERATIONS.md)의 실행 명령·출력 폴더·기능 설명은 이 모드에만 해당합니다.

Python 3.10 이상과 FFmpeg/ffprobe가 설치된 컴퓨터에서 저장소 또는 ZIP의 **전체 폴더**로 실행합니다.

```bash
bash run-norn.command
# 또는 원본 폴더 직접 지정
bash run-norn.command "/원본사진영상폴더"

# 설치 진단
python3 engine/main.py --diagnose

# 공개 웹 UI와 고급 로컬 엔진을 연결할 때만
python3 engine/main.py "/원본폴더" --web-origin https://norn.designboard.net
```

실행 도우미는 `.venv`를 준비하고 Pillow가 없으면 설치합니다. Mac에서는 원본 폴더 선택창을 제공합니다. 브라우저 연결 토큰은 공유하지 않고, 엔진 종료 시 터미널에서 Control+C를 누릅니다. 같은 출력 폴더에 엔진을 여러 개 실행하지 않습니다. 설치·플랫폼별 실행은 사용 환경에서 확인합니다.

기존 FFmpeg 설치를 사용하며 Homebrew 환경의 설치 명령은 `brew install ffmpeg`입니다. HEIC/HEIF 처리가 필요하면 `.venv` 활성화 후 `python3 -m pip install -r requirements-heic.txt`를 실행합니다. 브라우저의 HEIC/HEIF 지원과 이 Python 추가 패키지는 별개입니다.

로컬 AI 분석에는 Ollama의 이미지 입력 지원 모델이 필요합니다. 기본 모델명은 `qwen3.5:4b`이며 실제 설치한 모델명을 지정할 수 있습니다. 분석 버튼을 눌렀을 때만 실행하고 원격 모델로 자동 대체하지 않습니다. 영상당 기본 5장 표본은 영상 전체 내용이나 말소리를 분석한 결과가 아니므로 추천 구간·사실관계를 직접 확인합니다.

이 고급 엔진은 원본 폴더 옆의 `원본폴더업로드준비`에 편집 JSON, `generated/`의 MP4, `sns/`의 문구, `exports/`의 게시 안내 ZIP과 캐시·아카이브를 저장합니다. **기존 엔진의 게시 ZIP은 문구·안내·첨부 경로를 담는 방식**이며, 생성 영상을 포함하는 브라우저 게시 ZIP과 구성 범위가 다릅니다. 원본은 복사·이동·삭제·업로드하지 않습니다. 엔진 결과에는 로컬 경로나 개인 내용이 포함될 수 있으므로 공개 공유할 파일은 내용을 확인합니다.
