[기본 흐름 PR](https://github.com/softm/norn/pull/1), [재생 준비·진단 보완 PR](https://github.com/softm/norn/pull/2), [영상 생성 타이머 보완 PR](https://github.com/softm/norn/pull/3)을 `main`에 병합했습니다. | 출력·게시 준비 | 실제 완성 영상 다운로드, 영상·편집 JSON·채널별 게시문·첨부 안내를 담는 ZIP, 지원 환경에서 사용자가 선택한 출력 폴더에 저장 |

| 엔진 캐시 회귀 수정 | 임시 파일 정리·미리보기 캐시 저장 이후 완료 상태를 공개. 완료 직후 같은 편집을 요청해도 캐시를 재사용하도록 경합 수정 |

세부 사용 방법은 [README](../README.md), 작업·복원·출력 규칙은 [브라우저 작업 흐름](BROWSER_WORKFLOW.md)을 참고합니다. 위 표는 구현 범위이며, 모든 기기에서의 실행 검증 완료를 뜻하지 않습니다.

## 원본과 결과 저장

| 항목 | 처리 방식 |
|---|---|
| 원본 사진·영상·음악 | 사용자가 선택한 파일을 브라우저에서 읽습니다. 원본을 서버에 업로드하거나 결과 폴더로 복사·이동·삭제하지 않습니다. |
| 편집 JSON | 장면·문구·구간·설정과 재연결용 파일 식별정보를 저장합니다. 원본 파일과 임시 Blob URL은 포함하지 않습니다. |
| 새로고침·다른 기기에서 복원 | 편집 JSON을 연 다음 같은 원본 파일·폴더를 다시 선택합니다. 편집정보 저장은 원본 백업을 대신하지 않습니다. |
| 기본 결과 저장 | 완성 영상 또는 `원본폴더명업로드준비.zip`을 다운로드합니다. 폴더명이 없으면 프로젝트 제목을 사용합니다. |
| 영상·게시자료 ZIP | 실제 생성한 MP4/WebM, `norn-project.json`, 결과 정보, SNS별 게시문과 첨부 안내를 담습니다. 원본 미디어는 포함하지 않습니다. 게시자료만 저장한 묶음에는 완성 영상이 없음을 안내합니다. |
| 폴더 직접 저장 | 지원 브라우저에서 사용자가 출력 위치와 쓰기를 별도로 허용합니다. 기존 출력과 겹치지 않는 새 폴더에 결과를 저장하며, 미지원 환경에서는 ZIP 다운로드를 사용합니다. |

입력 폴더 선택은 부모 폴더의 쓰기 권한을 주지 않습니다. 원본 옆에 결과 폴더를 자동 생성하는 기존 Python 엔진의 동작을 브라우저 기본 저장 방식으로 약속하지 않습니다. SNS 업로드는 사용자가 게시문과 파일을 확인한 뒤 직접 수행합니다.

## 브라우저 생성 범위와 한계

| 항목 | 현재 범위 |
|---|---|
| 원본 보관함 | 프로젝트당 최대 **600개** 자료 |
| 타임라인 | 버전당 최대 **120개** 장면 |
| 완성 영상 길이 | 한 편 최대 **10분** |
| 영상 배속 | **0.25~4배속**. 기기가 해당 배속을 재생하지 못하면 오류 안내 |
| 출력 해상도 | 480p·720p(기본)·1080p 선택. 최대 **1080p 수준**, 장변 1920px 및 총 1920×1080 픽셀 이내. 세로 영상도 같은 총 픽셀 한도 적용 |
| 출력 형식 | **H.264·AAC MP4** 녹화 지원을 확인해 MP4를 선택. 해당 조합을 지원하지 않으면 지원되는 **WebM** 사용. MIME과 확장자를 맞추며 코덱을 지정하지 않은 MP4 지원만으로 형식을 선택하지 않음 |
| 생성 방식 | **실시간 합성·녹화**. 완성 영상 길이 정도의 시간에 준비·마무리 시간이 더해지며 작업 탭을 유지해야 함 |
| 메모리·파일 크기 | 생성 영상 최대 512MB 및 예상 크기 사전 제한. 해상도·FPS·길이의 조합에 따라 먼저 제한될 수 있음 |
| 원본 형식·효과 | 브라우저에서 디코딩 가능한 원본과 구현된 글씨·전환 범위. 지원하지 않는 코덱·배속·효과는 오류 안내 |

이 한도는 모든 조합·기기에서의 성능 보장이 아닙니다. 긴 고해상도 원본, 4K 출력, 120배속 타임랩스, 모든 FFmpeg 효과, 프레임 단위의 정확한 오프라인 렌더링을 브라우저에서 제공한다고 표시하지 않습니다. 음성 전사와 실제 AI 내용 분석은 기본 자동 구성에 포함하지 않습니다.

| 루트 경로 UI·정적 빌드 | **통과** | 루트·`public/`·빌드 결과의 홈/편집/진단 경로와 실제 모듈 로딩 |
| Firestore 에뮬레이터 | **11개 통과** | 실제 SDK 저장·읽기·삭제·충돌 및 계정별 권한. 운영 OAuth 승인을 대신하지 않음 |
| 0.3.0 운영 배포 | **배포·실제 출력 확인** | 공개 주소의 파일·폴더 선택 화면, 실제 사진 2장·영상 1장 선택과 편집 JSON 다운로드, 예제 3장면의 480p WebM 생성·다운로드·파일 재생 길이·장면 변화 확인 |
| 운영 Firebase·Google 로그인 | **이번 작업에서 새로 검증하지 않음** | 기본 파일·폴더 편집에는 로그인 불필요. 기존 운영 설정을 새로 구성했다고 주장하지 않음 |
| 개발/CLI 의존성 감사 | **12건 잔존: 높음 8·보통 4** | 이번 CI의 `dependency-audit` 기록. 브라우저 편집을 위해 새 npm 의존성을 추가하지 않았으며 강제 다운그레이드나 경고 숨김을 하지 않음 |

브라우저 단독 검사는 Linux에서 **실제 창을 띄운 Chromium**으로 640×480 합성 사진·영상·음악을 사용했습니다. 첫 native 영상 재생을 **600.3ms 지연**시켰고, 이 지연은 녹화 전 준비 단계에서 처리됐습니다. 화면 갱신 콜백도 녹화 전 **1,007.6ms**, 녹화 중 **1,029.2ms** 지연되도록 비동기 지연을 넣어 페이지의 화면 갱신과 영상 생성 시계를 분리한 동작을 확인했습니다. 실제 타이머 처리 500ms 및 영상 재생 오차 350ms의 중단 기준은 유지했습니다. 결과는 **720×1280 WebM, VP8/Opus, 계획 8.5초·실제 8.469초**였습니다. 영상 장면은 3초에 시작하며 초반 원음 RMS는 3077.50, 앞뒤 사진 구간은 각각 0.00·0.28로 측정해 소리가 준비 구간이나 사진 구간에 섞이지 않았음을 확인했습니다. ZIP의 CRC와 영상 바이트 일치, 원본 미포함, 원본 SHA-256 불변을 검사했습니다. 페이지 오류·콘솔 오류·실패 응답·로컬 엔진 요청·업로드 요청은 0건입니다. 테스트에서는 실제 설정 파일을 읽은 뒤 Firebase만 브라우저 컨텍스트에서 비활성화했습니다.

운영 원격 브라우저에서는 사진 2장과 영상 1장의 선택·편집, 3,832바이트 JSON 다운로드를 실제 확인했습니다. JSON에는 장면 3개·8.5초 길이·수정 문구가 보존되며 임시 Blob URL은 없었습니다. 초기 영상 검사에서는 페이지가 visible인데도 화면 갱신 콜백 간격이 약 1초로 지연돼 중단됐습니다. 이후 영상 생성 시계를 화면 갱신과 독립된 FPS 타이머로 바꾸고 같은 원격 브라우저에서 다시 확인했습니다.

최종 운영 검사에서는 사이트의 **사진 예제 3장면을 480×854 VP8 WebM으로 생성하고 실제 다운로드**했습니다. 파일 크기는 **1,341,657바이트**, 계획 길이는 **9초**, 실제 패킷 기준 길이는 **8.963초**입니다. 영상 패킷 268개와 1초 간격으로 디코딩한 9개 화면을 확인했고, 1·4·7초 장면의 픽셀 변화로 첫 화면이 정지된 파일이 아님을 검사했습니다. 실제 타이머 정지·영상 재생 오차에 대한 중단 기준은 완화하지 않았습니다. 운영 예제 출력 확인과 CI의 실제 로컬 원본·원음 포함 720p 출력 검사는 서로 다른 검사이며, 운영 원격 브라우저에서 사용자 원본의 모든 형식·고해상도를 시험한 것은 아닙니다.

이 결과는 모든 브라우저·OS·장시간 원본·모바일 기기의 성능 보장이 아닙니다. 폴더 직접 저장 권한과 MP4 인코더 지원도 기기별로 다릅니다. 실제 사용자 원본과 Google OAuth 승인을 시험 데이터나 에뮬레이터로 대신 검증했다고 표시하지 않습니다.
