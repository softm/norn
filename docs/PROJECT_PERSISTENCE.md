# 프로젝트 자동 저장과 복원 · NORN 0.6.0

기준일: 2026-10-22 (한국 시간). 파일을 추가하고 화면을 나가도 프로젝트에 자료와 편집 내용이 남도록 저장 경로를 통합한다.

## 사용자가 보는 동작

| 작업 | 저장·복원 동작 |
|---|---|
| 사진·영상·음악 추가 | 선택한 원본의 바이트와 썸네일을 이 브라우저에 보관한다. 보관 트랜잭션이 끝나야 자료 추가 완료를 표시한다. |
| 제목·장면·자막·효과·음악 설정 수정 | 변경 즉시 편집 복구 기록을 남기고 프로젝트를 자동 저장한다. 로그인 상태이면 Firebase에도 편집 정보가 동기화된다. |
| 프로젝트 저장 버튼 / Ctrl·Cmd+S | 실제 브라우저 프로젝트 저장을 완료하고, 로그인 상태에서는 계정 저장도 실행한다. |
| 편집 파일 백업 (JSON) | 별도의 백업 다운로드다. 이 동작이 계정 저장 성공 표시를 대신하지 않는다. |
| 홈·워크스페이스 이동 / 다른 프로젝트 열기 | 현재 프로젝트를 보관한 뒤 이동한다. 자료 보관함도 프로젝트별로 분리한다. |
| 같은 기기·브라우저에서 새로고침 / 재방문 | 저장된 파일로 새 객체 URL을 만들고 자료·타임라인·설정을 복원한다. 원본 재선택이 기본 절차가 아니다. |
| 로그인한 계정에 저장된 작업이 없는 경우 | 기존 0.5.5 동작을 유지해 편집기를 바로 연다. 이 브라우저에 복구할 작업이 있거나 목록 조회가 실패하면 빈 프로젝트를 추가 생성하지 않는다. |
| 계정 저장 지연·오프라인 | 최신 브라우저 보관본을 유지하고 계정 저장 대기·재시도 상태를 표시한다. |
| 저장 공간 부족·권한 차단 | 저장 실패를 표시한다. 원본 파일이 보관되지 않았는데 완료로 안내하지 않는다. |
| 프로젝트 삭제 | 해당 프로젝트와 더 이상 참조되지 않는 브라우저 보관 자료만 삭제한다. 컴퓨터에 있는 실제 원본 파일은 수정하지 않는다. |

## 저장 위치

| 저장 대상 | 위치 | 범위 |
|---|---|---|
| 원본 사진·영상·음악, 썸네일 | IndexedDB `norn-local-projects-v1` | 사이트 주소·브라우저 프로필별 보관, 계정 UID/guest로 분리 |
| 현재 편집, 선택 장면, 계정 저장 기준 버전 | IndexedDB 프로젝트 레코드 | 프로젝트별 독립 보관 |
| 아직 처리 중인 최신 편집 | 동기식 localStorage 복구 기록 | 닫기 전에 비동기 저장이 끝나지 못한 경우 복구 |
| 로그인 사용자의 편집 정보와 저장 이력 | 기존 Firebase `users/{uid}/projects/{projectId}` | 원본 바이트·Blob URL·로컬 절대 경로는 전송하지 않음 |
| 완성 영상 | 기존 다운로드 / 결과 저장 기능 | 생성된 영상은 탭을 닫기 전에 다운로드 |

원본 파일을 출력 폴더로 복사하거나 이동하지 않는다. 브라우저 안에는 재방문을 위한 별도 보관 데이터가 생기므로 원본 크기만큼 사이트 저장 공간을 사용할 수 있다. 동일 계정의 여러 프로젝트가 같은 파일을 사용하면 내용 해시를 기준으로 바이트를 재사용한다.

## 복원 범위

같은 사이트 주소·브라우저 프로필에서 보관된 원본을 복원한다. 다른 기기나 다른 브라우저 프로필, 시크릿 모드 종료, 사이트 데이터 삭제·브라우저 저장 공간 정리 이후에는 원본을 다시 연결해야 할 수 있다. 계정에 동기화된 편집 설정은 그대로 불러오고 SHA-256·종류·크기로 원본을 연결한다. 0.6.0 적용 전에 닫혀서 사라진 메모리상의 원본을 새 기능이 소급 복구할 수는 없다.

네트워크 읽기가 지연되면 이 브라우저 보관본으로 작업을 연다. 다른 기기의 최신 편집과 복구본이 충돌하면 어느 한쪽을 덮어쓰지 않고 별도 복구 프로젝트를 만든다.

## 검증

- Node 저장 계층 검사: 파일·썸네일 바이트 복원, 동기식 복구 기록, 중복 파일 재사용, 계정 분리, 지연된 클라우드 저장 응답, 저장 공간 부족, 공유 파일 삭제 보호.
- 실제 Chromium·IndexedDB 회귀 검사: `tests/ui-persistence.py`. Firebase 어댑터만 명시적인 테스트용 구현으로 교체하며 원본 File·IndexedDB·새로고침·화면 이동은 실제 브라우저 동작을 사용한다.
- 기존 `tests/ui-browser.py`: 원본 사진·영상·음악 4개를 같은 브라우저에서 새로고침해 복원한 뒤 영상 생성과 ZIP 다운로드를 검증한다. 새로운 브라우저의 JSON 가져오기·원본 재연결 검사도 유지한다.
- 운영 Google OAuth와 사용자의 기존 개인 프로젝트에 대한 쓰기 검증은 위 테스트로 대체하지 않는다. 운영 원본을 시험 자료로 사용하지 않는다.
