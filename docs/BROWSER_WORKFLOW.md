# 노른 · 브라우저 작업 흐름

기준: **2026-10-19**

## 1. 서비스 기본 흐름

일반 사용자는 [노른](https://norn.designboard.net/)에 접속해 자신의 사진·영상 또는 폴더를 선택하고, 같은 브라우저에서 장면 편집과 영상 생성을 마친 뒤 결과를 저장합니다. Python 명령 실행, FFmpeg 설치, 로컬 서버 시작, 연결 토큰 입력은 기본 작업의 전제 조건에서 제외합니다.

| 항목 | 브라우저 기본 흐름 | 별도 고급 엔진 흐름 |
|---|---|---|
| 시작 | 사이트에서 파일·폴더 선택 | 설치된 로컬 Python 엔진 실행 |
| 원본 접근 | 사용자가 선택한 `File`과 임시 객체 URL | 사용자가 지정한 로컬 경로 |
| 영상 생성 | 브라우저의 미디어 기능 | 네이티브 FFmpeg |
| 자동 구성 | 자료·길이 설정을 이용한 규칙 기반 배치 | 연결된 Ollama 모델의 표본 분석 가능 |
| 결과 형식 | 실제 지원·생성된 MP4 또는 WebM | 엔진이 생성하는 MP4 |
| 기본 결과 저장 | 다운로드 | 원본 옆 업로드준비 폴더 |
| 폴더 직접 저장 | 지원 브라우저에서 별도 출력 위치·쓰기 허용 | 사용자 운영체제의 파일 쓰기 권한 |
| 로그인 | 계정별 편집 저장을 쓸 때 선택 | 계정별 편집 저장을 쓸 때 선택 |

이 문서는 사용 흐름과 구현 계약입니다. 개별 기능의 코드 반영, 테스트 결과, 배포 결과는 서로 다른 상태로 기록하며, 문서 작성만으로 완료 표시를 하지 않습니다.

## 2. 화면과 사용자 행동

| 화면·상태 | 사용자가 하는 일 | 앱이 해야 할 일 |
|---|---|---|
| 첫 진입 | 작업 시작 | 파일·폴더 선택으로 바로 연결합니다. 계정 연결을 강제하지 않습니다. |
| 자료 선택 | 사진·영상·음악을 여러 개 선택하거나 폴더를 선택 | 읽을 수 있는 자료의 썸네일·재생 시간·크기를 확인하고 읽지 못한 항목을 알립니다. |
| 편집 | 장면 추가·삭제·순서·구간·문구·비율 조정 | 원본 대신 편집 상태를 수정합니다. 미연결 원본과 지원하지 않는 설정을 표시합니다. |
| 자동 구성 | 자료와 목표 길이에 맞는 기본 배치 요청 | 규칙으로 배치했다는 사실을 알려줍니다. 연결하지 않은 AI의 분석 결과를 만들지 않습니다. |
| 생성 | 현재 버전의 영상 생성 | 실제 지원 형식과 제한을 확인한 뒤 처리 상태·취소·오류·완료를 표시합니다. |
| 저장 | 영상 또는 게시 준비 묶음 다운로드 | 실제 결과 형식·파일 크기·현재 편집과의 관계를 표시합니다. |
| 다시 열기 | JSON 또는 계정 프로젝트 열기 | 편집정보를 복원하고 원본을 다시 선택하도록 안내합니다. |

기술 용어와 고급 서버 연결 설정은 해당 기능을 명시적으로 선택했을 때 설명합니다. 파일을 선택한 다음 “화면 편집용이며 실제 생성에는 로컬 엔진이 필요하다”는 안내로 기본 흐름을 중단하지 않습니다.

## 3. 파일·폴더 선택과 원본 보존

### 입력 방식

파일 선택은 `<input type="file" multiple>`을 기본으로 하고 사진·영상·음악을 받을 수 있도록 합니다. 폴더 선택은 `webkitdirectory` 입력을 사용하며 하위 폴더 파일의 상대 경로를 자료 목록 표시에 활용할 수 있습니다. 해당 입력 기능이 제공되지 않는 환경에는 다중 파일 선택을 제공합니다. 드래그 입력이 제공되더라도 파일 선택 버튼은 유지합니다.

선택 목록에 있다고 모든 파일이 영상에 사용되는 것은 아닙니다. 문서나 지원하지 않는 미디어는 자료로 잘못 분류하지 않고 제외 원인을 알립니다. 파일 크기·개수 등 처리 한도가 있으면 선택 단계에서 확인하고, 한도를 넘긴 자료를 몰래 누락한 채 전체 성공으로 표시하지 않습니다.

### 원본 참조

사용자가 선택한 `File` 객체와 `URL.createObjectURL()`로 만든 임시 URL을 보관해 재생·썸네일·렌더링에 사용합니다. 원본을 출력 폴더로 복사하거나 파일 전체를 Base64 문자열로 만들어 편집 JSON에 넣지 않습니다. 읽기·해시 계산·디코딩을 위해 브라우저가 데이터에 접근하는 것과 원본의 영구 복사본을 만드는 것은 별개입니다.

프로젝트 교체나 자료 해제 시에는 더 이상 쓰지 않는 임시 URL을 해제합니다. 생성 중인 파일의 참조가 먼저 사라지지 않도록 취소·완료 순서와 정리를 관리합니다. 원본에 쓰는 파일시스템 핸들은 기본 입력 과정에서 요구하지 않습니다.

객체 URL의 생성·해제 동작은 [MDN의 `createObjectURL()` 문서](https://developer.mozilla.org/en-US/docs/Web/API/URL/createObjectURL_static), 폴더 입력은 [MDN의 `webkitdirectory` 문서](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory)를 기준으로 합니다.

## 4. 편집 저장과 원본 다시 연결

편집 프로젝트와 원본 접근 권한을 분리합니다. 새로고침 뒤 제목·장면이 복원되어도 임시 파일 URL이 재사용될 것으로 가정하지 않습니다.

| 항목 | JSON·계정 프로젝트에 저장 |
|---|---|
| 제목·설명·공개 소개글 | 허용 |
| 버전·순서·구간·배속·글씨·출력 설정 | 허용 |
| SNS 채널별 사용자 수정 문구 | 허용 |
| 파일 식별 ID·종류·크기·SHA-256 | 허용 |
| 원본 파일 내용·썸네일·영상 표본 | 제외 |
| 절대 경로·임시 객체 URL·파일시스템 핸들 | 제외 |
| 고급 엔진 주소·인증 토큰 | 제외 |

복원 절차는 다음과 같습니다.

1. JSON 또는 계정에 저장된 편집 상태를 읽고 스키마를 검증합니다.
2. 사용자가 원본 파일 또는 폴더를 다시 선택합니다.
3. 선택한 원본의 식별정보를 계산해 저장된 파일 종류·크기·해시와 대조합니다.
4. 유일하게 일치한 자료만 연결합니다. 동일 파일명이라는 이유만으로 다른 내용의 파일을 사용하지 않습니다.
5. 누락 자료와 중복 후보를 알리고, 미연결 장면이 있는 동안 완전한 결과가 만들어진 것처럼 처리하지 않습니다.

게스트의 브라우저 임시 저장은 원본 백업이 아닙니다. 계정 저장 역시 편집정보 저장이며 사진·영상 업로드 서비스로 안내하지 않습니다. 복원·원본 다시 연결 과정에서 기존 장면 순서와 사용자의 수정 문구를 보존합니다.

## 5. 브라우저 영상 생성

### 실제 결과 형식

브라우저 녹화 기능의 지원 형식 확인은 `MediaRecorder.isTypeSupported()`와 실제 생성 결과를 함께 사용합니다. 지원 표시가 있어도 시작·디코딩·녹화가 실패할 수 있으므로 처리 오류를 별도로 다룹니다. 결과의 MIME, 확장자, 다운로드명, ZIP 내부 파일명은 일치해야 합니다. 관련 API 동작은 [MDN의 `isTypeSupported()` 문서](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/isTypeSupported_static)를 참고합니다.

| 조건 | 처리 |
|---|---|
| MP4 녹화 가능·실제 MP4 생성 | `.mp4` 결과 제공 |
| MP4 미지원·WebM 생성 가능 | `.webm` 결과 제공, 화면에 WebM 표시 |
| 필수 녹화 기능 없음 | 원인과 가능한 결과 저장 범위를 알림. 가짜 영상 파일 생성 금지 |
| 원본 코덱을 읽을 수 없음 | 파일별 오류 표시. 빈 장면으로 조용히 대체하지 않음 |
| 렌더링 설정 미지원 | 생성 전에 해당 설정·조정 방법 안내 |
| 처리 취소·실패 | 미완성 결과를 완료로 표시하지 않음 |

### 편집 효과와 처리 한도

| 항목 | 렌더러 기준 |
|---|---|
| 해상도 | 가로·세로 각각 최대 1,920px, 전체 픽셀 수 최대 2,073,600. 1,080×1,920 세로 가능 |
| 프레임레이트 | 10~60fps |
| 출력 타임라인 | 최대 600초·120장면 |
| 영상 배속 | 0.25~4배속. 재생 엔진이 해당 값 설정에 실패하면 오류 |
| 사진 움직임 | `none`, `zoom` |
| 글씨 스타일 | 기존 10개 스타일 |
| 전환 | `cut`, `fade`, `fadeblack`, `fadewhite`, `wipeleft`, `wiperight`, `wipeup`, `wipedown` |
| 원음 | 장면 `keep_audio`, 전체 음소거, 원음 볼륨 |
| 배경음악 | 사용자가 선택한 로컬 오디오의 볼륨·시작점·반복·페이드 인·아웃 |

기존 FFmpeg의 전환·고배속·고해상도 기능이 모두 브라우저에도 구현된 것으로 간주하지 않습니다. 렌더링 미지원 설정은 내보내기 전에 오류로 안내합니다. 예를 들어 `120배속` 타임랩스, 목록에 없는 전환, 4K 출력을 임의로 저배속·다른 전환·저해상도로 바꾸지 않습니다.

### 처리 상태와 자원

브라우저는 Canvas 합성 화면과 오디오를 `MediaRecorder`로 실시간 녹화합니다. 일반적으로 결과 영상 길이 정도의 처리 시간에 원본 준비·마무리 시간이 더해집니다. 설정 FPS는 느린 기기에서 해당 프레임 수의 처리 성능을 보장하지 않습니다. 생성 중 작업 탭을 유지하고, 탭 숨김처럼 정상 처리에 영향을 주는 상태가 감지되면 중단·다시 시작 안내를 제공합니다.

읽기·준비·합성·파일 마무리·완료를 구분하고, 계산할 수 있는 실제 작업량에 기반해 진행률을 표시합니다. 전체 작업량을 알 수 없는 단계에는 임의의 백분율을 주지 않습니다. 사용자가 취소하면 재생·녹화·오디오·타이머를 정리합니다.

필요한 현재·다음 장면을 중심으로 자료를 준비하고, 결과 영상·ZIP이 사용하는 브라우저 메모리에도 한도를 둡니다. 긴 영상·고해상도 원본의 성능을 보장하지 않습니다. 편집한 이후 이전 결과가 남아 있으면 현재 편집으로 만든 최신 결과와 구분합니다. 생성 과정에서 실패한 결과로 기존 완성 파일을 교체하지 않습니다.

## 6. 결과 저장과 게시 준비 ZIP

| 결과 | 포함 내용 | 원본 포함 |
|---|---|---|
| 영상 다운로드 | 현재 버전의 실제 MP4/WebM | 아니요 |
| 편집 JSON | 편집 상태·설정·식별 메타데이터 | 아니요 |
| SNS 문구 | 채널별 게시 텍스트 | 아니요 |
| 게시 준비 ZIP | 생성 영상, 편집 JSON, SNS 문구·안내 | 아니요 |

생성한 영상은 게시 준비 ZIP에 포함합니다. 경로 텍스트만 넣고 영상까지 제공했다고 표시하지 않습니다. 기존 Python 엔진의 텍스트·첨부 경로 중심 ZIP과 브라우저 ZIP의 구성을 문서·UI에서 구분합니다.

기본 출력은 브라우저 다운로드입니다. 폴더에 직접 저장하는 기능은 `showDirectoryPicker()`와 쓰기를 지원하는 환경에서 사용자가 직접 출력 위치를 선택하고 허용할 때 사용합니다. 이 기능을 지원하지 않거나 사용자가 선택을 취소하면 다운로드를 계속 사용할 수 있도록 합니다.

원본 폴더를 읽기 위해 선택한 입력값만으로는 부모 폴더 쓰기 권한을 얻을 수 없습니다. 따라서 원본 폴더 옆에 `원본폴더업로드준비`를 자동 생성하는 네이티브 엔진 동작을 웹사이트의 기본 저장 방식으로 약속하지 않습니다. 지원 환경과 사용자 동작 요구 사항은 [MDN의 `showDirectoryPicker()` 문서](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)를 참고합니다.

## 7. 자동 구성과 AI

기본 구성 버튼은 선택한 자료, 순서, 길이, 사용자가 입력한 제목·설명에 대한 규칙을 적용합니다. 모델이 연결되어 있지 않다면 사진의 사물·사람·사건, 영상의 행동·대화 내용을 이해했다고 표시하지 않습니다. 파일명이나 사용자의 입력에서 얻은 정보와 실제 AI 분석 결과를 구분합니다.

Ollama 기반 표본 분석은 고급 엔진에 연결한 경우의 별도 기능입니다. 기본 브라우저 편집·생성을 위해 설치하도록 요구하지 않습니다. 외부 AI 서비스나 별도 브라우저 모델을 향후 추가할 때에는 연결 방식, 전송 자료, 사용자 실행 동작을 명시적으로 설계하고 아직 없는 기능을 현재 지원으로 안내하지 않습니다.

## 8. 기존 기능과 운영 문서

기존 프로젝트 스키마, 버전별 편집 상태, Firebase 편집 저장, Python 엔진 코드를 가능한 범위에서 함께 유지합니다. 브라우저 기본 흐름을 추가한다는 이유로 기존 저장 프로젝트를 삭제하거나 파일명만으로 다른 원본을 연결하지 않습니다.

## 9. 완료 판단 기준

다음 항목은 브라우저 단독 흐름을 검증할 때 확인할 조건입니다. 이 표는 검증 결과표가 아니며 실제 실행 결과는 별도로 기록합니다.

| 구간 | 확인할 조건 |
|---|---|
| 기본 진입 | 로그인·로컬 서버·Python 설치 없이 작업실에 진입 |
| 입력 | 다중 파일과 폴더 선택, 미지원 파일 표시, 선택 취소 시 기존 작업 유지 |
| 원본 보존 | 원본 바이트의 서버 전송·영구 복사·이동·삭제·수정 없음 |
| 편집 | 사진·영상 장면의 순서·구간·문구·비율이 생성 결과에 반영 |
| 영상 | 실제 파일이 생성되고 다시 재생됨. MIME·확장자·파일명이 일치 |
| 실패·취소 | 완료를 가장하지 않음. 자원과 진행 상태 정리 |
| 복원 | JSON 복원 후 원본 재선택·해시 재연결, 누락·중복 후보 표시 |
| 게시 ZIP | 생성 영상과 JSON·SNS 문구 포함, 원본 제외 |
| 저장 위치 | 폴더 직접 저장 미지원 환경에서도 다운로드 동작 |
| 회귀 | 기존 Python 엔진·계정 저장 검사와 브라우저 검사를 구분해 확인 |
| 운영 | 소스·빌드·테스트·실제 배포·실제 기기 검증 상태를 각각 기록 |
