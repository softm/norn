# 2026-10-18 · NORN Firebase 연결 보완

중단된 작업을 다시 조사한 결과 `softm/norn` main에는 웹 편집기·로컬 엔진·Firebase 연동 코드가 이미 반영되어 있었습니다. 기존 파일을 보존하고 연결·배포 진단 기능을 보완했습니다.

## 이번 변경

| 변경 | 실제 내용 |
|---|---|
| 연결 도우미 | 기존 수동 SDK 복사 대신 실제 CLI 프로젝트/앱 조회와 선택, 공개 SDK 자동 검증·백업·저장 |
| 안전한 배포 | 조회된 Hosting 사이트 선택과 기본 Rules 전체 교체 경고. 사용자 승인 후만 실행 |
| 계정 진단 | `setup.html`에서 설정·Google 로그인·Firestore 읽기를 분리. 원본 업로드/자동 쓰기 없음 |
| Firebase 초기화 | 초기화 중복 실행 방지, 실패 재시도, 관리자 키/토큰 거부, 설정/프로젝트 불일치 차단 |
| 에러 안내 | 도메인 미승인·Google 미활성·팝업 차단·권한 거부 등 안내 |
| Pages | 자동 활성화 권한 오류를 반복하지 않고 미설정/실제 배포를 별도로 표시 |

## 이번 실행에서 확인

- Node 도메인 7 + 설정/보안/도우미 테스트 7: **14개 통과**.
- Python 엔진: 실제 HTTP/FFmpeg를 포함한 **10개 통과**.
- Chromium 오프라인 화면: **11항목 통과**. 제목 편집, 복제/삭제/이동, 독립 출력 버전, 콘셉트, SNS, 390px 화면, 상단 진행 표시.
- 기존 GitHub Actions의 Firestore 에뮬레이터 5개 검사는 실제 성공 결과를 조회했습니다. 이 문서는 운영 Firestore Rules를 배포했다고 주장하지 않습니다.
- 새 연결 도우미는 dry-run과 SDK fixture로 검사했습니다. 사용자 계정으로 프로젝트 생성/등록/배포를 실행한 것은 아닙니다.
- 브라우저 UI 검사는 네트워크 차단 환경의 오프라인 DOM 방식입니다. 실제 Google OAuth와 사용자 Mac ↔ 배포 도메인의 로컬 연결은 미검증입니다.

## 남아 있는 외부 승인

Firebase 플러그인은 마지막 조회에서 미설치였습니다. ChatGPT 설치 카드 승인과 Google 권한 승인을 대신 처리한 적이 없습니다. 실제 NORN Firebase 프로젝트 식별값과 인증 연결이 없으므로 기본 웹 설정은 비활성 상태를 유지합니다.

Pages도 저장소 관리자 권한으로 초기 활성화가 필요합니다. 기존 실행 로그의 실패는 `Get Pages site: Not Found`와 `Create Pages site: Resource not accessible by integration`입니다. 소스 반영·검사 통과와 공개 배포 성공을 구분합니다.

다른 서비스의 Firebase 프로젝트, 운영 데이터, 관리자 키, 사용자의 원본은 가져오지 않았습니다. 폰트 파일도 이 패키지에 포함하지 않습니다.
